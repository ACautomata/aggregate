# ADR-0002：部署拓扑 —— 后端独立部署，tailscale / ssh 访问 gauss

- **状态**：accepted（2026-08-24）
- **范围**：盲评前后端「前端 + 后端」与 gauss、sugon 的部署关系，以及评审者浏览器如何到达界面。

## 背景

用户方案：`评审者浏览器 → [前后端服务器] → gauss（唯一数据库）`。后端服务器将来会部署到**其他服务器**（当前未定具体机器）。gauss 与后端服务器之间用户建议「部署 tailscale 并连接到高斯，也可使用 ssh」。评审者访问后端服务器一段的路径尚未确定。

## 决定

1. **后端服务器独立于 gauss 部署**；它在 tailscale（首选）或 ssh 隧道（备选）上访问 gauss 的 PostgreSQL。
2. **前端 + 后端同一 Node 进程**：Fastify 服务既提供 API，也托管构建后的前端静态文件，单端口对外。
3. **评审者访问后端服务器**（该段未定机组）按**双模式**设计，文档与配置用占位符：
   - **模式 A（公网入口 / 推荐）**：后端服务器有可达入口，评审者经 HTTPS 访问；由 Caddy 或 Nginx 反向代理 + 自动证书。
   - **模式 B（内网 / 校园网或医院网）**：后端服务器与 gauss 同处内网，评审者在同一内网直连；无外网暴露，DUA 更稳。
4. **受控字段不越界**：`source` / `case` / `image_path` 只存在于 gauss 数据本体内部，任何 API 响应与前端界面都不得携带；后端在数据本体层分离「评审可见字段」与「受控字段」。

## 考虑过的替代

- **评审者直连 gauss**：被「数据保存在 gauss + 前后端分离」排除；评审者不应触达数据本体。
- **后端也放 gauss**：违背用户「后端另行部署到其他服务器」。

## 后果

- 后端服务器需安装 Node + pm2（非 root，用户目录静态 tarball），tailscale 客户端（或保留 ssh 隧道脚本）。
- gauss PG 监听绑定 tailscale 接口（或 localhost 供隧道），`pg_hba` 只放行后端服务器；不开放公网。
- 模式未定 → 部署文档以占位符呈现，给出每台目标机器的配置清单与选择说明。
